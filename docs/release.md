# Релиз и автообновление

Обновление приложения — через `tauri-plugin-updater` в ручном режиме:
проверка и установка только по кнопке «Проверить» в разделе «Диагностика».
Технически это замена бандла штатным NSIS-установщиком в тихом режиме —
ручная переустановка не нужна, приложение перезапустится само.

## Как обновляется клиент

1. Кнопка «Проверить» запрашивает
   `https://github.com/urodstvo/discord-music-activity/releases/latest/download/latest.json`.
2. Если версия в `latest.json` новее текущей — показывается кнопка
   «Установить X.Y.Z» с заметками релиза.
3. Установка скачивает подписанный `.nsis.zip`, проверяет подпись
   (pubkey в `src-tauri/tauri.conf.json` → `plugins.updater`) и запускает
   установщик. Отдельного relaunch не нужно.

## Версии: три файла

Версия продублирована, все три места обязаны совпадать:

- `package.json` → `version`
- `src-tauri/tauri.conf.json` → `version`
- `src-tauri/Cargo.toml` → `version`

Проверка: `pnpm check-versions`. CI (`ci.yml`) и релизный workflow
падают при рассинхроне.

## Как выпустить релиз

1. Подними версию во всех трёх файлах одинаково, закоммить в `main`.
2. Поставь тег и запушь:
   ```bash
   git tag v0.6.0
   git push origin v0.6.0
   ```
3. Workflow `release.yml` проверит совпадение тега и версий, соберёт
   Windows NSIS-бандл, подпишет артефакты апдейтера и создаст
   **DRAFT**-релиз с файлами `.exe`, `.nsis.zip`, `.nsis.zip.sig`,
   `latest.json`.
4. Проверь draft-релиз вручную (установка + обновление со старой версии),
   затем нажми Publish. После публикации `latest.json` станет доступен
   клиентам как `releases/latest/download/latest.json`.

Пререлизов нет: любые `v*`-теги публикуются как обычные релизы (draft).

## Секреты репозитория (Settings → Secrets → Actions)

| Секрет | Откуда |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | Приватный minisign-ключ (содержимое файла ключа целиком). Сгенерирован локально, хранится только здесь и в надёжном месте. |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Пароль ключа. Если ключ без пароля — оставить пустым (поле можно не задавать). |
| `DISCORD_APPLICATION_ID` | Application ID из Discord Developer Portal. Обязателен release-сборке (`src-tauri/build.rs`). |

Публичный ключ уже вписан в `tauri.conf.json` (`plugins.updater.pubkey`).
Приватный ключ никому не передавать и в git не класть.

## Смена ключа подписи

Старые клиенты знают только старый pubkey. Ротация — в два релиза:

1. Выпустить промежуточную версию, подписанную старым ключом, где pubkey
   уже заменён на новый (клиенты подтянут новый ключ через обновление).
2. Следующие релизы подписывать новым ключом.

Без шага 1 клиенты со старым ключом новое обновление отвергнут.
